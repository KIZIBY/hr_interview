# Stage 1 — Creative Team, консолидированный отчёт

Дата: 2026-07-12 · Creative Director: оркестратор (Opus) · субагенты: Brainstormer, Critical Analyst, System Analyst, Hard Critic (Sonnet, параллельно)

## Сводка позиций

**Brainstormer** — 5 user stories (подготовка / экстренная подсказка / диалог / переход из пульта / оценка), 4 альтернативы:
A) третья вьюшка в interviewer.html; B) отдельный guide.html + ссылка; C) guide.html + micro-памятка в пульте; D) guide.html с deep-link `#task-ID`. Рекомендовал C.

**Critical Analyst** — 11 рисков, топ: случайная демонстрация гайда при шаринге экрана (критический, митигация — баннер + правило гигиены); дрейф трёх источников истины (митигация — рендер памятки из tasks.json, не копии); гайд как «скрипт для зачитывания» (митигация — структура «тема → что ищем → маркеры», не «вопрос → ответ»); ложный NO-GO на нестандартном корректном ответе (митигация — блоки «принятые варианты», ML-предупреждения, чеклисты багов для DBG-задач); объём (лимит 15 минут на подготовительную часть).

**System Analyst** — фактура: в tasks.json 13 задач (7 из PRD — todo-authoring, физически отсутствуют); у 5 задач (discussion/design) `referenceSolutions` пустые — норма, памятка строится из `evaluationNotes`+сигналов; sync.js гайду не нужен; SEGMENTS/CRITERIA дублировать статически с комментарием синхронизации (выносить в config.json — оверинжиниринг для 11 строк); candidate.html не трогается; один self-contained guide.html; деплой pure additive.

**Hard Critic** — 5 оспариваний: (1) памятка = второй рендер tasks.json, пульт уже показывает эталоны; (2) HTML-переверстка interview-process.txt не решает «не-мидл собеседует мидла» — решают дословные формулировки и дифференциаторы ответов, которых нигде нет; (3) интерактив (поиск/фильтры/localStorage) — YAGNI; (4) «вся информация» — scope creep, зафиксировать границу; (5) третий источник истины. Минимальный scope: скрипт первых 5 минут, антивайб-формулировки дословно, дифференциатор «как звучит 1/3/4», печатный оценочный лист.

## Решения Creative Director (синтез)

1. **Оспаривание №1 Hard Critic отклонено частично, с фактурой:** пульт показывает детали только выбранной задачи, а выбор = мгновенный показ кандидату (QA-отчёт, наблюдение №1 — предпросмотра не существует). Безопасно листать решения можно только вне пульта → памятка в гайде имеет самостоятельную ценность. Micro-памятка в пульте (альтернатива C Brainstormer) отклонена как дублирование: пульт уже рендерит эталоны выбранной задачи.
2. **Принята архитектура D+B:** один standalone guide.html, рендер памятки из tasks.json (fetch, single source of truth), deep-link `#task-<ID>` из деталей задачи в пульте, ссылка «Гайд» в topbar.
3. **Принят минимальный scope Hard Critic как ядро подготовительной части:** скрипт первых 5 минут, дежурные антивайб-зонды дословно, маркеры «как звучит 1/3/4» по зонам, печатный оценочный лист (@media print). Поиск/фильтры/localStorage — Out of Scope.
4. **Приняты все митигации Critical Analyst:** баннер безопасности первым элементом, ML-предупреждения (mlSpecific), чеклисты багов для DBG-02/03, блоки «принятые варианты», лимит 15 минут/2500 слов на подготовительную часть, @media print, дата актуальности в шапке.
5. **Дублирование SEGMENTS/CRITERIA** — статически с комментарием `sync: interviewer.js` и сноской «действующее правило считает пульт» (по System Analyst; риск дрейфа 2.2/2.3 Critical Analyst принят осознанно как trade-off против лишней инфраструктуры).

Результат: `spec.md` (FR-1…FR-12, NFR-1…5, edge cases, out of scope).

## Открытые вопросы к stage-2

- Достаточно ли «баннер + приватный репо» как митигации утечки для формата шаринга экрана — или требовать отдельного окна браузера для гайда (инструкция в баннере)?
- Печатный оценочный лист: только вёрстка @media print или отдельная секция-«карточка» в начале гайда?
- Формулировки «как звучит 1/3/4» — какой объём достаточен (по 1 строке на балл на зону?), чтобы не раздуть документ.
