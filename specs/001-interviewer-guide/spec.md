# Spec 001 — Гайд интервьюера и памятка решений (guide.html)

- Статус: stage-1 draft
- Дата: 2026-07-12
- Источник: фраза владельца (голос, /pipeline): «подготовить гайд для интервьюера — аккумулированный HTML-документ, встроить в платформу как раздел; вся информация как проходить собеседование (флоу, этапы, что спрашивать, темы) + памятка по заданиям с решениями; чтобы человек, который сам не тянет на мидла, мог собеседовать кандидата на мидл-позицию»

## Overview

Одна standalone HTML-страница `guide.html` в дизайн-системе X5 — рабочий документ интервьюера технического этапа №2 (FDE Middle+). Закрывает две потребности:

1. **Подготовка (до интервью, ~15 минут чтения):** флоу 60-минутного этапа, пять зон проверки, готовые речевые формулировки («скрипт первых 5 минут», антивайб-зонды дословно), маркеры сильных/слабых ответов, правило вердикта GO/NO-GO.
2. **Экстренная подсказка (во время интервью):** памятка по каждой задаче банка — эталонные решения, принятые варианты, сигналы «берём/стоп», follow-up вопросы — в 1–2 клика, по якорю.

Ключевое обоснование памятки (ответ на YAGNI-возражение «пульт уже показывает эталоны»): в пульте детали задачи видны только после её выбора, а **выбор задачи мгновенно показывает её кандидату** (подтверждено QA-отчётом `docs/qa/2026-07-12-e2e-landings.md`, наблюдение №1 — режима предпросмотра не существует). Гайд — единственное место, где интервьюер может безопасно листать решения до и во время интервью, не засвечивая задачи кандидату.

Целевой пользователь: инженер-интервьюер, который сам слабее кандидата («не прямо тянет на мидла»). Отсюда редакционный принцип: не «вопрос → эталонный ответ», а «тема → что ищем → как звучит хороший/слабый ответ → что спросить дальше» + фразы, которые можно произнести дословно. Гайд — ориентир, не скрипт для зачитывания (установка фиксируется в шапке документа).

Источники контента (не выдумывать): `Техническое интевью этап №2, что спрашивать в целом.docx` (флоу, зоны, сигналы, памятка), `Middle+ Forward Deployed Engineer.docx` (контекст роли), `tasks.json` (13 задач: referenceSolutions, greenSignals, redSignals, followUps, evaluationNotes).

## User Stories

- **US-G1 (подготовка).** Как интервьюер перед первым этапом №2, я хочу за 15 минут понять структуру 60-минутного интервью, что проверяется в каждом сегменте и как принимается решение GO/NO-GO, чтобы выйти на встречу без страха «не знаю, что спрашивать».
- **US-G2 (экстренная подсказка).** Как интервьюер, не уверенный в правильности прозвучавшего ответа, я хочу быстро открыть памятку конкретной задачи (эталон, принятые варианты, сигналы), чтобы продолжить диалог осмысленно, не показывая задачи кандидату.
- **US-G3 (диалог).** Как интервьюер, не знающий, копать глубже или переходить дальше, я хочу видеть follow-up вопросы задачи и дежурные антивайб-зонды в формулировках, которые можно произнести дословно, чтобы вести содержательный диалог.
- **US-G4 (переход из пульта).** Как интервьюер с выбранной задачей в пульте, я хочу одним кликом открыть её карточку в памятке (`guide.html#task-<ID>`), чтобы не искать вручную.
- **US-G5 (оценка).** Как интервьюер, выставляющий оценки, я хочу видеть расшифровку каждого критерия и как звучит «1»/«3»/«4», чтобы оценка была осмысленной, а не интуитивной.

## Functional Requirements

- **FR-1.** Страница `guide.html` — standalone, в корне проекта, X5 DS (`colors_and_type.css` первым импортом, X5 Sans, `--x5-ink`, логотип снизу слева, без эмодзи, sentence case).
- **FR-2.** Первый видимый элемент — предупреждающий баннер: документ только для интервьюера; инструкция — открывать гайд в отдельном окне браузера (не в окне/профиле, из которого идёт демонстрация), закрыть/свернуть перед шарингом экрана. При печати сохраняется плашка «документ конфиденциальный — не передавать кандидатам» (не скрывается @media print).
- **FR-3.** Секция «Флоу этапа»: таймбокс-таблица шести сегментов (0–5 разогрев … 55–60 вопросы; значения продублированы из `interviewer.js` SEGMENTS с комментарием-якорем синхронизации) + «что делаю в этом отрезке». Тактика сегментов: скрипт первых 5 минут — ровно два смысловых хода (установка безопасной атмосферы «разговор, не экзамен» + открытый вопрос про последний агентский проект с инструкцией фиксировать называемые технологии для зондов сегмента 5–18); сегмент 34–48 — правило выбора задачи «под зону, где не хватает сигнала», не по порядку; сегмент 48–55 — правило выбора слабой зоны (наименьший текущий балл → туда, задачей или дозондом); сегмент 55–60 — дежурные ответы на вопросы кандидата и скрипт next step (2–3 предложения). Правило перехода между зонами: получил сигнал раньше таймбокса → переходи; таймбокс истёк без сигнала → один уточняющий вопрос и переходи.
- **FR-4.** Секция «Пять зон проверки» (CS-фундамент, system design, проектирование агентов, прод-зрелость, AI-augmented практика): для каждой — что проверяем; антивайб-зонды как параметрический паттерн из источника — три шаблона с переменной X, где X — любая технология из речи кандидата («что у X под капотом?», «что будет, если убрать X?», «почему X, а не Y?»); маркеры «как звучит 1 / 3 / 4» (по одной фразе на балл, выводятся из greenSignals/redSignals задач зоны и шкалы источника: 1 = стоп-сигнал дословно, 3 = «называет и объясняет, норма Middle+», 4 = «сам называет trade-offs и failure modes без наводящих»); стоп-сигналы. Плюс блок «Речевые мосты — что говорить в сложной ситуации», три дословные реплики: кандидат молчит → «можешь думать вслух — мне интересен ход рассуждений»; ушёл не туда → «а если посмотреть со стороны надёжности/состояния?»; интервьюер не понял ответ → «объясни, как объяснял бы коллеге, который с этим не работал». Контент — из interview-process источника.
- **FR-5.** Секция «Памятка по задачам»: карточки всех задач из `tasks.json`, рендер в браузере через `fetch('tasks.json')` (single source of truth — новые задачи подхватываются без правки гайда). Карточка: ID+название+категория+сложность+таймбокс задачи; условие кратко; эталонные решения с notes (формат code); для discussion/design задач с пустым `referenceSolutions` — эталонное содержание из `evaluationNotes`, и карточка открывается disclaimer-блоком: «это рубрика для оценки хода рассуждения, не чеклист дословных совпадений — другие термины с тем же смыслом засчитываются»; принятые варианты; greenSignals/redSignals; followUps. Якорь `id="task-<ID>"` на каждой карточке. Все строковые поля tasks.json при рендере экранируются функцией `esc()` (по образцу `interviewer.js:70-74`); прямая вставка сырых полей в `innerHTML` запрещена.
- **FR-6.** Для задач с `mlSpecific: true` — заметное предупреждение: «требует ML-контекста; без ML-опыта возьмите соинтервьюера или другую задачу».
- **FR-7.** Для debug-задач со списком багов в `evaluationNotes` (DBG-02, DBG-03) — представление списком-чеклистом (визуально; без сохранения состояния), чтобы интервьюер мог отмечать найденное глазами; пороговое число засчитывания из `evaluationNotes` («достаточно N+», «сильный — M+») выносится на карточку явно, рядом с чеклистом.
- **FR-8.** Секция «Оценка и вердикт»: пять критериев с весами и стоп-строками, шкала 1–4 с расшифровкой, правило GO/NO-GO (средневзвешенное ≥ 3.0, без «1» в стоп-строках — стоп-строки перечислить поимённо: CS-фундамент, проектирование агентов, прод-зрелость; «2» в остальных не блокирует), сквозные сигналы «берём/стоп» этапа, и блок «Памятка» — шесть пунктов источника дословно (стек не критерий / фундамент критерий / больше слушаем / аналоги — плюс / алгоритмика — инструмент, не цель / оценку зафиксировать в течение 10 минут). Значения продублированы из `interviewer.js` CRITERIA с комментарием синхронизации + сноска «действующее правило считает пульт».
- **FR-9.** Якорная навигация: sticky-оглавление (флоу / зоны / задачи / оценка) + список задач в оглавлении памятки.
- **FR-10.** Интеграция с пультом: ссылка «Гайд» в topbar `interviewer.html` (`target="_blank" rel="noopener"`); в деталях выбранной задачи — ссылка «Памятка по задаче» → `guide.html#task-<ID>` (тот же target/rel).
- **FR-11.** Печать: `@media print` — скрыть навигацию/баннер-кнопки, разумные разрывы страниц; секция «Оценка и вердикт» помещается на один лист A4 как печатный оценочный лист.
- **FR-12.** При недоступности `tasks.json` (открытие как file://) — секция памятки показывает понятную ошибку с инструкцией запуска http-сервера (по образцу пульта); остальные секции работают.

## Non-Functional Requirements

- **NFR-1 (объём/читаемость).** Подготовительная часть (флоу + зоны + оценка, без памятки задач) читается за ≤ 15 минут: ориентир ≤ 2500 слов. Памятка задач — справочная, вне лимита.
- **NFR-2 (производительность).** Страница статическая; сетевые запросы — только локальные к своему origin: `fetch('tasks.json')` для памятки и `fetch('interviewer.js')` для SYNC-guard (введён аудитом stage-2, R-3); рендер 13+ карточек ≤ 200 мс на ноутбуке интервьюера; без внешних CDN.
- **NFR-3 (совместимость).** Работает в актуальных Chrome/Safari/Firefox; вёрстка без горизонтального скролла на 1440/1024/768 px; 375 px — не целевой сценарий, но без поломки чтения.
- **NFR-4 (сопровождаемость).** Контент задач не дублируется в HTML (рендер из tasks.json). Продублированные константы (SEGMENTS, CRITERIA) помечены комментарием `<!-- sync: interviewer.js -->`; в шапке гайда — дата актуальности процессной части.
- **NFR-5 (доступность).** Семантическая разметка заголовков (h1–h3), якорная навигация с клавиатуры, focus-visible; контраст по токенам X5.

## Authentication & Access

N/A — входа/ролей/SSO в продукте нет (статические страницы, одна машина интервьюера; `team.params: SSO_PROVIDER="-"`).

Замечание безопасности (вне механизмов аутентификации): guide.html лежит на том же origin, что candidate.html, и технически доступен кандидату по URL — как и tasks.json, который целиком (с эталонами) отдаётся по прямому запросу без фильтрации: это принятое ограничение архитектуры статики, а не дефект гайда. Модель угроз принята владельцем для формата «одна машина интервьюера»; инварианты гигиены: кандидату шарится исключительно вкладка candidate.html, пульт interviewer.html кандидату не демонстрируется никогда, URL сервера кандидату не передаётся. Главный реальный вектор — случайная демонстрация вкладки при шаринге экрана — митигируется баннером FR-2 (отдельное окно) и print-плашкой конфиденциальности. Публичный деплой платформы запрещён (репозиторий приватный).

## Out of Scope

- Поиск, фильтры, чеклисты с сохранением состояния (localStorage) — не тот масштаб (единицы интервью в неделю).
- Soft skills, бизнес-кейс, коммуникация с заказчиком, HR/юридические темы — другие этапы воронки (явно из interview-process источника).
- Изменения `candidate.html`, `sync.js` (гайду синк не нужен — read-only документ), схемы `tasks.json`.
- Подсветка текущей задачи пульта в гайде в реальном времени (v2, если понадобится).
- Серверная защита гайда от кандидата (бэкенд/авторизация) — вне архитектуры статики.
- Авторинг новых задач (7 задач PRD в статусе todo-authoring — отдельная работа; гайд подхватит их автоматически при появлении в tasks.json).

## Affected Services

- **Новый файл:** `guide.html` (self-contained: разметка + inline-стили поверх токенов + inline-скрипт рендера памятки; отдельный guide.js не требуется).
- **interviewer.html:** +1 ссылка «Гайд» в topbar; в `renderDetails()` (interviewer.js) +1 ссылка «Памятка по задаче» с якорем. Другие изменения запрещены.
- **candidate.html / candidate.js / sync.js / tasks.json:** без изменений.
- **X5_Group_Design_System/:** используется read-only.

## Edge Cases

- Задача с пустым `referenceSolutions` (PY-01, PY-02, SD-01, AGT-01, AIP-01 — форматы discussion/design): карточка строится из `evaluationNotes` + сигналов + followUps; блок «эталонные решения» не показывается пустым.
- `tasks.json` недоступен/невалиден → FR-12 (ошибка только в секции памятки).
- Задача без `followUps`/`greenSignals` → соответствующий блок карточки скрывается, не рендерится пустой заголовок.
- Открытие `guide.html#task-XXX` с несуществующим ID → страница открывается сверху без ошибки.
- Печать при развёрнутой памятке: карточки задач не рвутся посреди блока кода (page-break-inside: avoid).
- Кандидат открыл guide.html по URL → принятое ограничение модели угроз (см. Authentication & Access); интервьюеру — правило гигиены из баннера.

## Assumptions

- Формат «одна машина интервьюера» (кандидат видит только candidate.html через второй экран/шаринг конкретной вкладки) — из брифа платформы.
- 13 задач текущего tasks.json достаточно для v1 памятки; todo-authoring задачи PRD вне scope.
- Владелец процессной части гайда — владелец репозитория; правило «поменял SEGMENTS/CRITERIA или процесс — обнови guide.html» фиксируется в CLAUDE.md на stage-3.
- Скрипт первых 5 минут и формулировки «как звучит 1/3/4» — редакционная работа stage-3 на основе interview-process источника (сигналы и зоны там есть; дословные фразы дописываются, не противореча источнику), в рамках, заданных FR-3/FR-4.
- Контракт якорей памятки фиксирован: `id="task-{task.id}"`; изменение шаблона требует синхронной правки ссылки в `renderDetails()` interviewer.js (зафиксировать в CLAUDE.md на stage-3).

## Success Criteria

- Интервьюер, не проводивший этап №2, после 15 минут с guide.html называет: структуру 60 минут, пять зон, правило GO/NO-GO, три антивайб-зонда — без подглядывания (проверка владельцем на себе).
- Из пульта до карточки любой задачи в памятке — ≤ 2 клика; карточка содержит эталон/принятые варианты/сигналы/follow-ups из tasks.json.
- Добавление 14-й задачи в tasks.json появляется в памятке без правки guide.html.
- Страница проходит браузерный смоук: без ошибок консоли, fetch 200, вёрстка 1440/1024/768 без горизонтального скролла, print-preview оценочного листа — один лист A4.
