# Plan 001 — Гайд интервьюера (guide.html)

- Дата: 2026-07-12 · stage-2 audit → план реализации
- Спека: `specs/001-interviewer-guide/spec.md` (FR-1…FR-12 после правок аудита)
- Scope: feature · Units of Work: `uw-1-code`, `uw-2-content`

## Архитектура

Один новый standalone-файл `guide.html` (разметка + inline-стили поверх токенов X5 + один inline `<script>`), плюс две точечные правки пульта. Никаких новых JS-файлов, зависимостей, изменений sync.js/candidate.html/tasks.json.

Поток данных: `DOMContentLoaded` → статические секции уже в DOM (баннер, флоу, зоны, оценка) → `fetch('tasks.json')` → `renderCards()` в контейнер памятки → снять `aria-busy` со секции. Ошибка fetch → в секции памятки notice с инструкцией http-сервера (образец — `showLoadError()` interviewer.js); остальные секции работают (FR-12). Открытие как file:// — unsupported, инструкция в notice.

Структура документа (заголовки h1 → h2 → h3 → h4, уровни не пропускать):

1. Баннер конфиденциальности (FR-2) — первый элемент DOM; текст остаётся при печати.
2. «Как пользоваться» — 3 строки: ориентир не скрипт; читать за 15 минут до; гайд в отдельном окне.
3. «Флоу этапа» (FR-3) — таймбокс-таблица 6 сегментов + тактика (скрипт 0–5 двумя ходами, правило выбора задачи 34–48, правило слабой зоны 48–55, next step 55–60, правило перехода).
4. «Пять зон проверки» (FR-4) — 5 подсекций + параметрические антивайб-зонды + маркеры 1/3/4 (по одной фразе) + речевые мосты (3 реплики).
5. «Памятка по задачам» (FR-5–FR-7) — рендер из tasks.json; оглавление задач; карточки `<article id="task-{id}">`.
6. «Оценка и вердикт» (FR-8) — критерии/веса/шкала/правило GO-NO-GO (стоп-строки поимённо) + сквозные сигналы + блок «Памятка» (6 пунктов дословно); print: `page-break-before: always`, компактный размер — помещается на A4.

## Units of Work

### uw-1-code — каркас, рендер, интеграция (кодовая часть)

1. **guide.html скелет:** `colors_and_type.css` первым; шапка-топбар по образцу пульта (заголовок + дата актуальности процессной части); sticky-оглавление; логотип X5 снизу слева; `<meta name="robots" content="noindex">`.
2. **Layout:** двухколоночный grid (TOC | контент) с `min-width: 0` на обеих ячейках (урок issue #9); ≤900px — одна колонка, TOC статичен/скрыт; высота топбара — CSS-переменная `--topbar-h`, sticky TOC `top: var(--topbar-h)`, все якорные цели `scroll-margin-top: calc(var(--topbar-h) + 16px)`.
3. **Рендер памятки:** копии `esc()` и `mdLite()` из interviewer.js c комментарием `// копия из interviewer.js — синхронизировать при изменении`; карточка задачи: meta-строка (ID, категория, сложность, вес×dimension, таймбокс, ML-бейдж), условие (mdLite), examples-таблица, эталоны с notes / или evaluationNotes-рубрика с disclaimer для discussion/design, «принятые варианты», сигналы, followUps, чеклист багов + порог для DBG. Все поля — только через `esc()`/`mdLite()`.
4. **Сигналы без эмодзи (CRITICAL F-1):** CSS-кружки 8px `var(--x5-success)`/`var(--x5-danger)` через `::before`; эмодзи-паттерн пульта не воспроизводить.
5. **Код в карточках (CRITICAL F-2):** `pre { overflow-x: auto; white-space: pre; max-width: 100% }` — горизонтальный скролл локализован в pre, body без переполнения (DBG-03 — строки до 97 символов).
6. **SYNC-guard (R-3):** SEGMENTS/CRITERIA продублированы в данных гайда; комментарий-контракт `SYNC-CONTRACT: interviewer.js` в обоих файлах; inline-проверка в гайде: если длины массивов/суммы весов расходятся с захардкоженными контрольными значениями — `console.warn` о возможном дрейфе.
7. **Интеграция с пультом (FR-10):** ссылка «Гайд» в topbar (`target="_blank" rel="noopener"`); в `renderDetails()` — ссылка «Памятка по задаче» на `guide.html#task-{id}`. Ничего больше в пульте не менять.
8. **Print (FR-11):** `@media print`: скрыть топбар/TOC/кнопки; плашку конфиденциальности оставить; `article { break-inside: avoid }`; секция оценки — `page-break-before: always`, компактные размеры (лист A4); `a[href]::after { content: none }`.
9. **A11y (NFR-5):** skip-link «к содержимому»; `:focus-visible` и `prefers-reduced-motion` по образцу пульта; `aria-busy` на секции памятки до конца рендера.
10. **CLAUDE.md:** зафиксировать контракт якорей `task-{id}` и правило «поменял SEGMENTS/CRITERIA/процесс — обнови guide.html».

### uw-2-content — редакционная часть (по источнику, не выдумывать)

1. Флоу-таблица и тактика сегментов — из interview-process источника (сегменты, «о чём говорим»), дописать только формат «что делаю» и правила выбора (FR-3), не меняя смысла.
2. Скрипт первых 5 минут — два смысловых хода (FR-3), 3–5 реплик по 2–3 строки, не монолог.
3. Пять зон: «что проверяем» из источника; зонды — три параметрических шаблона; маркеры «1/3/4» — по одной фразе на балл, выведенные из шкалы источника и greenSignals/redSignals задач зоны; речевые мосты — три реплики (FR-4).
4. Сквозные сигналы «берём/стоп» и блок «Памятка» из 6 пунктов — дословно из источника (FR-8).
5. Дежурные ответы 55–60 («что дальше» + next step) — 2–3 предложения, нейтральные к процессу найма.
6. **Бюджет объёма (CRITICAL R-1):** подготовительная часть ≤ 2500 слов; держать constraint с первого черновика: реплики, не параграфы; проверка перед коммитом: `wc -w` по тексту секций 2–4 и 6.
