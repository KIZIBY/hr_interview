# Constitution Check — gate-процедура

**Статус:** canonical · операционный канон enforcement'а конституции (см. [constitution.md](constitution.md), Часть III).
**Версия:** 1.0.1 (2026-07-02 — де-X5-изация формулировок: имена инвариантов читаются из Части I устава проекта, без смены механизма; spec 001)
**Трекинг:** [#3186](https://github.com/KIZIBY/hr_interview/issues/3186) (приёмка гейта в reference-инстансе X5).

**Что это.** Воспроизводимая процедура, которой stage-2 audit (`/pipeline-stage2`), ревьюер PR или агент сверяют спеку / план / дифф с Частью I конституции (инварианты I-1…I-16). Это и есть «авто-гейт» enforcement'а: переводит сверку из «если ревьюер вспомнил» в обязательный шаг с правилом блокировки.

## Принцип DRY

Процедура **не дублирует** формулировки инвариантов. Единственный источник истины — `docs/constitution.md`, Часть I. Здесь описано только КАК проверять и КАК блокировать. Путь устава — `docs/constitution.md` (одна константа; при переносе файла обнови ссылку здесь и в `pipeline-stage2`).

## Вход

Любой из: `spec.md`, `plan.md`, дифф / PR, или текстовое описание изменения.

## Процедура

1. Загрузи `docs/constitution.md` — Часть I (I-1…I-16) и Часть III (precedence).
2. Для **каждого** инварианта I-1…I-16 оцени вход по его строке «_Как проверить_»:
   - **PASS** — соответствует, либо обоснованно неприменим;
   - **N/A** — инвариант не затрагивается изменением (укажи, почему);
   - **FLAG** — изменение нарушает или вероятно нарушит инвариант (укажи, где и чем);
   - **NEEDS-INFO** — по входу инвариант оценить нельзя.
3. Не угадывай. Если данных не хватает — `NEEDS-INFO` + требование уточнить спеку, а не молчаливый PASS (I-13).

## Выход (обязательный формат)

| Инвариант | Severity | Вердикт | Обоснование |
|---|---|---|---|
| I-1 «имя из Части I устава» | MUST/SHOULD | PASS/N/A/FLAG/NEEDS-INFO | … |
| … (все инварианты Части I, по порядку, с их именами из устава) … | | | |
| I-16 «имя из Части I устава» | … | … | … |

**Итог:** `MUST-FLAG: N · SHOULD-FLAG: N · NEEDS-INFO: N`.

> Severity берётся из заголовка самого инварианта в Части I (MUST/SHOULD); частично-N/A инвариант оценивается по его применимой части.

## Правило блокировки

- **Любой `MUST-FLAG` = блокер этапа.** Спека не проходит stage-2 (и PR не мержится), пока нарушение не устранено в спеке **ИЛИ** не проведена явная versioned-поправка устава (Часть III), легализующая исключение. Молчаливый обход запрещён (I-11 / I-13).
- **`NEEDS-INFO` на MUST-инвариант** = блокер до уточнения (непроверенное не пропускаем — I-13).
- **`SHOULD-FLAG`** — предупреждение: фиксируется в `plan.md` → «Known Risks», не блокирует.

## Self-тест (приёмка гейта, issue #3186)

Гейт обязан на эталонах давать ожидаемый результат, иначе он сломан. Эталоны ниже сформулированы
на домене reference-инстанса X5 (устав-образец — [constitution.x5-reference.md](constitution.x5-reference.md));
при переносе гейта в другой проект пара spec-bad/spec-clean формулируется под его Часть I:

- **`spec-bad`** (новая multi-tenant таблица с прямым `SELECT` из handler'а, `OFFSET/LIMIT`-пагинация, без RLS/`company_id`, секрет в `compose.yml`, **новый user-facing-эндпоинт без capture/correlate-пути ошибок** — клиентские 5xx/JS-исключения никуда не собираются и не коррелируются по `request_id`) → как минимум **FLAG I-5** (нет `loadXForCaller`/RLS → риск кросс-тенант + existence-oracle), **FLAG I-15** (offset вместо keyset), **FLAG I-7** (секрет в compose), **FLAG I-16** (нет хотя бы одного из CAPTURE/CORRELATE/RETAIN/TRIAGE для пользовательских ошибок фичи); `MUST-FLAG ≥ 4`.
- **`spec-clean`** (read-endpoint: handler→service→repo, `loadXForCaller`+RLS+404, keyset-пагинация, RBAC↔enforcement, аудит мутаций, optimistic concurrency) → все MUST = PASS/N/A; `MUST-FLAG: 0`.

## Опционально: локальный git-хук (pre-commit)

Лёгкий локальный guard — `.githooks/pre-commit` (трекаемый), активируется `scripts/install-git-hooks.sh` (`git config core.hooksPath .githooks`, раз на клон/worktree). Это **напоминание**, не замена гейту: блокирует только однозначные секреты (I-7: `sk-live-` / `AKIA` / private key), варнит маркеры TODO/FIXME без `// TEMP: … #issue` (I-11) и `OFFSET`-пагинацию (I-15 шаблона устава — актуально в проектах с БД), напоминает прогнать полный гейт на изменённых спеках. Полная сверка инвариантов Части I требует LLM-суждения (Constitution Gate в stage-2) — shell её не делает. Разовый обход: `git commit --no-verify`.
