# QA-отчёт — E2E-прогон лендингов интервью (interviewer.html + candidate.html)

Дата: 2026-07-12 · база: `http://localhost:8000` (python3 -m http.server) · коммит: f0f0779

## Как проводился прогон

Агент Рената была заблокирована: в сессии отсутствовал Playwright MCP-транспорт
(`BLOCKED: visible-browser-required`), поэтому она отдала статический аудит кода
с гипотезами. Рантайм-прогон выполнен основным агентом через Playwright 1.61.1
(Chromium headless, один browser context, две вкладки — BroadcastChannel работает).
Скрипт прогона: `docs/qa/2026-07-12-e2e/e2e-run.mjs`, скриншоты — там же.
Три из четырёх подтверждённых дефектов предсказаны статическим аудитом Ренаты.

Итог: **44 проверки, 40 прошло, 4 подтверждённых дефекта** (одна изначально
упавшая проверка — J10, клавиатура на шкале оценок — переквалифицирована
в артефакт тест-скрипта: при чистом воспроизведении стрелки работают).

## Вердикт

**Собеседование по этим страницам вести можно** — весь основной контур
(банк задач, показ кандидату, зеркало кода, таймер с overtime, оценочный лист
с правилом GO/NO-GO, сброс, восстановление после перезагрузки) работает без
консольных ошибок. Дефекты ниже не блокируют живое интервью на ноутбуке,
но №1 и №2 стоит закрыть до первого боевого использования: оба бьют по
доверию интервьюера к тому, что он видит на экране.

## Подтверждённые дефекты

### 1. [major] Бейдж «кандидат подключён» — односторонний, залипает
Кандидат закрыл/перезагрузил вкладку — бейдж у интервьюера навсегда остаётся
«кандидат подключён». `setConnected(true)` вызывается на любое сообщение от
кандидата (`interviewer.js:423`), а `setConnected(false)` не вызывается нигде —
нет heartbeat/timeout. Репро: подключить кандидата → закрыть его вкладку →
бейдж не меняется (проверка H1).
Фикс-направление: heartbeat от кандидата раз в N секунд + таймаут у интервьюера.

### 2. [major] Смена задачи молча очищает зеркало кода
При выборе новой задачи `selectTask` обнуляет зеркало (`interviewer.js:237`),
и оно остаётся пустым до первого ввода кандидата — интервьюер теряет код,
который кандидат уже написал, без какого-либо индикатора (проверка G2).
При этом черновики у кандидата сохраняются per-task (проверка G1 прошла) —
данные не теряются, теряется видимость.
Фикс-направление: при смене задачи показывать плейсхолдер «ждём код по задаче X»
или подтягивать черновик по новой задаче через SYNC_REQUEST.

### 3. [minor] У зеркала кода нет метки свежести «обновлено HH:MM:SS»
Панель называется «Код кандидата — в реальном времени», но понять, живой это
код или зависший пятиминутной давности, нельзя (`interviewer.js:425-432`,
проверка E3). В связке с дефектом №1 интервьюер не может отличить
«кандидат думает» от «кандидат отвалился».

### 4. [minor] Переполнение вёрстки на 375px (31px у задач, ~31px у оценки)
Виновник — `.bank__filters select { flex: 1 }` без `min-width: 0`: интринсик-
ширина селектов распирает панель банка до 386px (проверка K1, диагностика
по getBoundingClientRect). Экран оценки переполняется таблицей шкалы (406px).
Страница кандидата на 375px чистая (K2 прошла). На ноутбуке интервьюера
не проявляется — но правится одной строкой CSS.

## Наблюдения (не дефекты, зафиксировать осознанно)

- **Клик по задаче в банке = мгновенный показ кандидату.** Кнопки «Показать
  кандидату» нет, хотя пустое состояние обещает её текстом («…и нажмите
  „Показать кандидату"», `interviewer.html:234`). Предпросмотра задачи без
  показа кандидату не существует — интервьюер не может «полистать банк»
  во время сессии. Решить: либо кнопка, либо поправить текст подсказки.
- **tasks.json целиком доступен кандидату по сети** (эталоны, сигналы, заметки).
  В DOM ничего не утекает — allowlist `CANDIDATE_FIELDS` работает (проверка D4,
  7 маркеров). Но кандидат с devtools увидит эталоны. Архитектурное ограничение
  статики без бэкенда; для внутреннего онбординга приемлемо, для реальных
  собеседований с удалённым кандидатом — нет (страницы задумывались для одной
  машины интервьюера, ок).
- **Черновик кандидата живёт в sessionStorage** — переживает F5 той же вкладки,
  но теряется при закрытии вкладки (проверка H3). By design, но стоит упомянуть
  в инструкции интервьюеру.
- **Эмодзи 🟢/🔴 в маркерах сигналов** (`interviewer.html:152-153`) — формальное
  нарушение жёсткого правила X5 «никаких эмодзи». Заменить на CSS-точки
  цветов `--x5-success`/`--x5-danger`.
- Фаза «оценка» персистится: перезагрузка страницы интервьюера возвращает
  прямо в оценочный лист — удобно и проверено (J9).
