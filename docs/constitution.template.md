## Часть I — Инварианты

#### I-1 — Data Sovereignty & Deployment Model (суверенитет данных)
**MUST.** [ЗАПОЛНИ: где живут данные и что запрещено. Примеры: «on-premise only, никаких
cloud-LLM/SaaS с прод-данными» (X5) · «данные в EU-регионе» · «SaaS допустим, кроме PII».]
- _Как проверить:_ спека/дифф не добавляет egress данных за заявленный периметр.

#### I-2 — Data is Sacred (данные священны)
**MUST.** Только soft-delete (`deleted_at`), миграции обратимы, append-only журналы не чистятся,
`.env`/конфиги окружений не перезаписываются деплоем. Пользовательские данные не теряются молча.
- _Как проверить:_ в диффе нет DELETE без soft-delete-обоснования, нет DROP/rewrite-миграций без бэкапа.

#### I-3 — Audit Immutability (неизменяемость аудита)
**MUST.** Журнал бизнес-событий append-only ([ЗАПОЛНИ: таблица/механизм, напр. `audit.events` +
SQL-триггеры на UPDATE/DELETE]). Мутации значимых сущностей аудируются.
- _Как проверить:_ новая мутация пишет audit-событие; триггеры/защита на месте.

#### I-4 — Clean Architecture (чистая архитектура)
**MUST.** [ЗАПОЛНИ: слои под свой стек; reference X5: handler → service → repository, зависимости
через интерфейсы, межсервисно — gRPC/события, чужая схема БД напрямую запрещена.]
- _Как проверить:_ дифф не протаскивает зависимость через слой / в чужую схему.

#### I-5 — Tenant/Access Isolation (изоляция доступа) — если многопользовательский/многотенантный
**MUST.** Каждая выборка скоупится вызывающим ([ЗАПОЛНИ: паттерн, напр. `loadXForCaller`],
изоляция fail-closed, чужой ресурс = 404 (не 403-оракул существования).
- _Как проверить:_ direct-ID чтение/мутация/экспорт чужого — denied; малформ-пейлоад не оракул.

#### I-6 — Frozen Contracts (замороженные контракты)
**MUST.** Обратная совместимость: [ЗАПОЛНИ: список замороженных поверхностей — формат
auth-токена/claims, схемы событий/очередей, proto/API-поля (не удалять/переименовывать), …].
- _Как проверить:_ дифф не меняет замороженную поверхность без versioned-решения владельца.

#### I-7 — Security by Default (безопасность по умолчанию)
**MUST.** Авторизация на каждом endpoint; RBAC и enforcement синхронны (право в UI = проверка на
бэке); только параметризованный SQL; секреты — env/secret-store, НИКОГДА в репо/логах/тикетах.
Вход — корпоративный SSO по `Product_agents/SSO_AUTH_GUIDE.md` (§3–4), роли — из групп каталога.
- _Как проверить:_ constitution-check по диффу; спека содержит `Authentication & Access`.

#### I-8 — Graceful Degradation (деградация без падения)
**MUST.** Отказ опциональной подсистемы ([ЗАПОЛНИ: AI/поиск/интеграции/…]) не роняет ядро.
- _Как проверить:_ выключенная подсистема → ядро работает, ошибка видима оператору (I-9).

#### I-9 — Observability (наблюдаемость)
**MUST.** Structured-логи, health-check и метрики на каждый сервис; user-facing ошибки
перехватываются и коррелируются request/trace-id, retention ≥ [ЗАПОЛНИ: 7д+]; всплеск ошибок
алёртится и заводится тикетом без ожидания жалобы пользователя.
- _Как проверить:_ у новой фичи ошибочные пути долетают до ingest с request_id (NFR_GUIDE §2).

#### I-10 — Deploy Safety (безопасный деплой)
**MUST.** Деплой только через [ЗАПОЛНИ: `{{DEPLOY_CMD}}`/скрипт]; миграции отдельно от кода
(expand-then-deploy), бэкап до; после деплоя — verify (health + smoke), откат описан.
- _Как проверить:_ дифф не вводит ручной деплой-шаг; у миграции есть Down/план отката.

#### I-11 — Production-Ready by Default (без MVP-заглушек)
**MUST.** Ноль stub/TODO/placeholder как финальное состояние; фича = код + тесты + докой;
workaround только помеченный `// TEMP: … см. #тикет`.
- _Как проверить:_ grep диффа на stub/TODO без тикета; DoD stage-4 зелёный.

#### I-12 — Root-Cause Discipline (дисциплина первопричины)
**MUST.** Любой баг — через systematic-debugging до доказанной первопричины; scope-the-class
(все оси повторения) + guard от регрессии. Канон: `docs/bug-handling-process.md`.

#### I-13 — Zero-Trust Verification (никому не верь на слово)
**MUST.** Claim (агента, CI, репортёра, своей памяти) принимается только со свежим собственным
evidence, желательно на другой оси. «FIXED» без перепроверки не существует.

#### I-14 — Code Speaks, Not Comments (код, а не комментарии)
**MUST.** Самодокументируемый код; комментарий-обещание запрещён; комментарий допустим только
для ограничения, которое кодом не выразить.

#### I-15 — Data Integrity Under Concurrency (целостность под конкуренцией)
**MUST.** Optimistic concurrency на конкурентных мутациях ([ЗАПОЛНИ: паттерн, напр.
`WHERE updated_at = $expected`]), bounded-выборки (keyset вместо OFFSET на растущих таблицах).

#### I-16 — Requirements Traceability (прослеживаемость требований)
**MUST.** Каждое требование спеки имеет след в плане и проверку в приёмке (`plan-lint` +
requirements-matrix stage-4); NFR квантифицированы (`Product_agents/NFR_GUIDE.md`).
