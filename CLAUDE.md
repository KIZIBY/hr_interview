## Что это за проект

Репозиторий готовит **материалы для собеседования на позицию Forward Deployed Engineer (FDE) уровня Middle+ → Senior** (по названию вакансии в репозитории; не путать с DevOps).

Результат каждой задачи — **самодостаточная HTML-страница-лендинг**, по которой интервьюер (ты или другой собеседующий) идёт вживую во время собеседования: листает секции с вопросами, кусками кода, ожидаемыми ответами. Всё оформляется под **дизайн-систему X5 Group** (см. раздел ниже), чтобы страницы деплоились единым набором (задачи, ответы и т.д.).

Замысел зафиксирован в `docs/project-brief.html` — это бриф-заметка, а не приложение (`index.html` в корне — навигационный хаб по страницам). Ключевые требования из брифа:
- результат сразу в формате HTML-страницы, по которой можно вести собеседование;
- лендинг листается сверху вниз; внутри — кусочки кода и, где уместно, **интерактив, исполняемый на стороне клиента** (в браузере, без бэкенда);
- всё делается **через тест-скилл и дизайн-систему онбординга** (см. ниже).

## Исходные материалы

Опирайся на входные `.docx` в `sources/` (не выдумывай содержание вопросов и «эталонных» ответов — бери из них):
- **`sources/Middle+ Forward Deployed Engineer.docx`** — описание вакансии; по нему калибруются уровень и темы.
- **`sources/Задачи на собеседование.docx`** — задачи с собеседования.
- **`sources/Техническое интевью этап №2, что спрашивать в целом.docx`** — сценарий технического интервью (этап №2), о чём спрашивать.

Отдельная задача проекта — **собирать лучшие практики других компаний** по найму FDE/инженеров и адаптировать их в вопросы/задачи.

## Дизайн-система: X5 Group Design System (обязательна)

Все страницы верстаются **по фирменной дизайн-системе X5**, которая лежит в репозитории: `X5_Group_Design_System/`. Это не референс «на посмотреть», а **источник истины по визуальному языку**: токены, шрифты, логотипы, шаблоны. Каноничное описание правил — `X5_Group_Design_System/README.md` и `X5_Group_Design_System/SKILL.md` (при конфликте README имеет приоритет).

**Как подключать (каждая страница):**
- импортируй `X5_Group_Design_System/colors_and_type.css` **первым** — там `@font-face` для X5 Sans и все токены в `:root` (`--x5-ink`, `--x5-grass`, `--x5-surface-*`, `--x5-divider` и т.д.); используй переменные, не хардкодь hex;
- шрифты и логотипы бери из `X5_Group_Design_System/fonts/` и `X5_Group_Design_System/assets/logos/` (копируй/ссылайся, не подменяй системными);
- образцы готовой вёрстки — `X5_Group_Design_System/slides/` (title, content, two-column, statement, kpi) и превью токенов — `X5_Group_Design_System/preview/*.html`.

**Жёсткие правила бренда — не нарушать (из SKILL.md):**
- шрифт только **X5 Sans Regular / Medium** — никаких Bold/Light и системных подмен;
- цвет основного текста — **`#303145` (`--x5-ink`)**, а не бренд-зелёный;
- логотип — **снизу слева, 0° поворота**, никогда не перекрашивать;
- **никаких эмодзи, восклицательных знаков и повелительных заголовков**;
- **sentence case** в заголовках и **длинное тире `—`** как системный разделитель; без висячих предлогов.

Визуальный характер системы — сдержанный, «executive/аналитический»: белый фон по умолчанию, плоские карточки (заливка/hairline `--x5-divider`, без цветного левого бордера), мягкие радиусы (8/16/999), спокойная моушен (120/200/320 мс, без bounce/parallax). Тон текста — русский, деловой; английские техтермины (`customer journey`, `D2C`, `AI-commerce`) не транслитерируются.

> Область дизайн-системы формально — «внутренние стратегические презентации X5». Мы переиспользуем её токены и правила для интервью-онбординга (тот же внутренний бренд). Если icon-set X5 недоступен, README разрешает подмену на **Lucide** — помечай такие места как временную подмену.

## Как собирать страницы: скилл `design-taste-frontend`

Любую генерацию или правку страниц веди **через скилл `design-taste-frontend`** (в брифе он назван «тест-скилл» — это транслитерация *taste skill*, не про тестирование ПО). Порядок работы, заданный скиллом:
1. прочитать бриф и выдать одну строку **«Design Read»** (тип страницы / аудитория / визуальный язык);
2. выставить три дайла — `DESIGN_VARIANCE` / `MOTION_INTENSITY` / `VISUAL_DENSITY` — и держаться anti-slop правил (никаких дефолтных AI-градиентов, трёх одинаковых карточек и т.п.);
3. отдавать самодостаточный HTML.

**Калибровка под этот проект:** аудитория — технический интервьюер, контекст — серьёзный корпоративный онбординг, страница нужна читаемой и «проходибельной» под диктовку. Это тянет к сдержанным пресетам (низкие/средние VARIANCE и MOTION, DENSITY достаточная для кода и вопросов), а не к «Awwwards-экспериментальному».

**Разделение ролей:** `design-taste-frontend` даёт мастерство и anti-slop-дисциплину (структура, ритм, «не выглядит как шаблон»), а **X5 Group Design System задаёт конкретный визуальный язык** (шрифт, цвета, токены, логотип, правила тона). При любом конфликте между вкусовыми дефолтами taste-skill и брендом — **выигрывают жёсткие правила X5**.

Смежные установленные скиллы, полезные здесь:
- `full-output-enforcement` — когда на странице много кода и нельзя допускать усечения/`// ...`;
- `minimalist-ui`, `high-end-visual-design` — альтернативные направления, если бриф это попросит;
- `redesign-existing-projects` — при доработке уже свёрстанных страниц (audit-first).

## Конвенции результата

- **Один артефакт = одна standalone HTML-страница**: без внешней сборки; хендбуки открываются двойным кликом, страницы платформы — через локальный http-сервер (fetch + синк вкладок).
- Интерактив и «запуск» кода — **только клиентские** (JS в браузере), чтобы страницу можно было деплоить как статику.
- Держи задачи и ответы структурировано (секция вопроса → секция ожидаемого ответа/критериев оценки), чтобы всё это легло в общий онбординг-набор.

## Структура репозитория

- **`platform/`** — продукт: `interviewer.html/js` (пульт), `candidate.html/js`, `guide.html`, `sync.js`, `tasks.json`. Страницы ссылаются на дизайн-систему через `../X5_Group_Design_System/` — переносить только вместе.
- **`handbooks/`** — самодостаточные хендбуки этапов 02 и 03 (визуальная серия задана хендбуком этапа 03, не X5 — осознанное исключение по решению владельца; хендбук 02 содержит встроенный снапшот tasks.json, пересобирать при изменении банка).
- **`sources/`** — исходные .docx и заметки; **`index.html`** — навигационный хаб; **`README.md`** — вход для людей.
- Превью: `python3 -m http.server 8000` из корня → `http://localhost:8000`. QA-скрипты (`docs/qa/2026-07-12-e2e/*.mjs`) используют BASE `http://localhost:8000/platform`.

## Контракты платформы интервью

- **Якорь карточки задачи в `platform/guide.html`:** `id="task-{task.id}"`. Ссылку строит `renderDetails()` в `platform/interviewer.js` — изменение шаблона якоря требует синхронной правки обоих файлов (спека 001).
- **Дублирование констант:** `platform/guide.html` статически дублирует `SEGMENTS` (таймбоксы) и `CRITERIA` (критерии/веса/стоп-строки) из `platform/interviewer.js` — помечено SYNC-CONTRACT-комментариями в обоих файлах; гайд сверяет значения через fetch и пишет `console.warn` при дрейфе. Поменял таймбоксы, критерии или процесс этапа — обнови таблицы в `guide.html`, дату актуальности в его шапке и пересобери хендбук этапа 02.

## Инфраструктура репозитория

- **Сборки и линтера нет.** Нет `package.json` — это статические HTML-страницы. Тесты есть: браузерные e2e на Playwright в `docs/qa/2026-07-12-e2e/` (e2e-run 44 проверки, guide-smoke 15, point-checks 5) — гонять при изменениях платформы.
