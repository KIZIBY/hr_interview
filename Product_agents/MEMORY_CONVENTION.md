# MEMORY_CONVENTION.md — единая конвенция персистентной памяти агентов

Status: ДЕЙСТВУЮЩАЯ (введена 2026-06-10, аудит-находки F-3/F-7).
Scope: все агенты `Product_agents/`. Индекс «агент → память → статус» — в
`Product_agents/Dev_Agents/AGENTS.md` → «Team Status & Memory Index».
Профили агентов НЕ дублируют эти правила — только ссылаются сюда (допустима
одна строка-указатель + агент-специфичные дельты). Сам memory-файл МОЖЕТ держать
краткий блок «Правила памяти» с агент-специфичными дельтами, но указатель на эту
конвенцию обязателен, и при расхождении конвенция главнее.

## 1. Имена файлов

- Канонический паттерн: `Product_agents/Dev_Agents/memmory_<Agent>.md`.
- Написание **`memmory`** (двойное «m») — закреплённая историческая опечатка-конвент.
  НЕ «исправлять»: половина инструментов и памятей агентов ссылается на эти пути.
- Legacy-исключения (сохраняются как есть, см. AGENTS.md «Preserve existing filename
  spelling»): `Masha_memmory.md`, `Pushkin/memmory.md`.
- Архив: каталог `memmory_<Agent>_archive/` рядом с компактом; файлы `<YYYY-MM>.md`.
  Для исторически смешанных блоков допустимы диапазоны/суффиксы:
  `2026-04_05-heartbeats.md`, `2026-05-runs.md`.

## 2. Двухуровневая структура

**Компакт** (`memmory_<Agent>.md`) — единственный файл, который агент обязан читать
перед прогоном. Hard-лимит: **1500 строк** (`wc -l`) **И ≤60 KB** (`wc -c`) — что
наступит раньше. Байтовый лимит добавлен 2026-06-21 (аудит памяти,
[[project_agent_memory_audit_2026-06-21]]): строковый лимит можно «легально» обойти,
удлиняя строки — `memmory_Renata.md` дорос до 179 KB при 1257 строках (~45k токенов
read-before-run) при формально соблюдённых 1500 строках. Стоимость чтения — это
ТОКЕНЫ (≈ байты/4), а не строки; активный агент платит её каждый прогон. Содержит:

- durable-слой (НЕ ротируется): правила памяти, снимок личности, coverage taxonomy,
  recurring patterns / issue clusters, известные слепые зоны, standing-rule checklists,
  routing, промахи и коррекции, lessons learned, open backlog, self-audit checklist;
- журнальный слой: минимум **последние 3 прогона** (полные записи);
- ⤵-указатели на отротированные блоки (что и куда переехало, с датой ротации).

**Архив** (`memmory_<Agent>_archive/*.md`) — полная история. Читается ТОЧЕЧНО
(grep по `#issue` / pack / дате), целиком НЕ читается и в read-before-run НЕ входит.

## 3. Инварианты (data sacred)

1. **Append-only.** Ничего не удаляется и не редактируется задним числом.
   Опровергнутая запись помечается `superseded: <дата> → see <new entry>`.
2. **Ротация = перенос, не правка.** Строки переезжают в архив БЕЗ изменений
   (byte-exact), на их месте остаётся одна ⤵-строка-указатель. Сверка обязательна:
   `строк(оригинал) == строк(новый компакт) + строк(перенесено) − указатели`.
3. **Никаких секретов.** Пароли, токены, cookies, session id, полные auth-заголовки —
   запрещены и в компакте, и в архиве, и в evidence.

## 4. Read-протокол (перед каждым прогоном)

1. Прочитать компакт **целиком** — правило снова физически выполнимо: до введения
   конвенции `memmory_Kulibin.md` был 15 224 строки (~320k токенов) и не влезал
   в контекст, т.е. BLOCKING-правило «читать целиком» молча нарушалось.
2. Без прочитанного компакта прогон не запускается.
3. Архив подключать точечно — по ссылкам из компакта или grep по конкретному вопросу.

## 5. Ротация — кто и когда

- **Сам агент**, в конце прогона: если компакт > 1500 строк **ИЛИ > 60 KB** —
  перенести старейшие журнальные записи (целые секции `## Run …`) в архивный файл
  месяца записи, оставить ⤵-указатель, выполнить сверку из §3.2, закоммитить вместе
  с memory-update. Журнал ротируется ПЕРВЫМ — он почти всегда покрывает перерасход.
- **Backstop — Dobivatel**: ежемесячный hygiene-sweep (см. `Dev_Agents/Dobivatel.md`):
  `wc -l -c Product_agents/Dev_Agents/memmory_*.md` → всё, что выше **строкового ИЛИ
  байтового** лимита, ротировать по этой конвенции; результат — в отчёт и в
  `memmory_Dobivatel.md`. Проверять обе метрики: файл бывает в лимите по строкам, но
  вдвое сверх по байтам (урок аудита 2026-06-21).
- Durable-секции не ротируются никогда; если durable-слой сам распух (мало строк, но
  много KB — как `memmory_Kulibin.md` 403 строки / 102 KB) — это сигнал на
  **консолидацию**: сгруппировать lessons по категориям, схлопнуть дословные повторы
  и избыточные ⤵-указатели. Консолидация ЛОССЛЕСС: ни один отдельный факт или `#issue`
  не теряется; при сомнении в уникальности — оставить. Удаление durable запрещено.
