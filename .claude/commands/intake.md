# /intake — хотелка одной фразой → тикет → спека → stage-1

Фраза владельца: **$ARGUMENTS**

**Единственный вход — `$ARGUMENTS`.** Внешние источники (webhook, e-mail, любые не-чатовые
входы) — вне scope; абстракцию «pluggable-источник intake» под них НЕ проектируй (FR-1, YAGNI).

## Границы команды (прочти до действий)

- **/intake ≠ bug-intake §1 и ≠ /pipeline** — это диспетчер ПЕРЕД ними: жалобы тоже сюда,
  команда сама маршрутизирует (баг → `docs/bug-handling-process.md` §1 без 4-этапного
  пайплайна; фича → тикет + спека + `/pipeline-stage1`). Владелец не обязан знать синтаксис
  `/pipeline` и сам классифицировать вход.
- **Граница redact:** `redact_tokens` применяется к выводу CLI внутри `scripts/intake.sh`,
  НЕ к тексту фразы владельца — случайно вставленный во фразу секрет/URL-с-токеном уедет
  в тикет дословно; секреты во фразе остаются ответственностью владельца (SEC-5).

## Шаг 1 — классификация bugfix/feature

Критерий — ТОТ ЖЕ, что в `/pipeline` шаг 0 (Scope) и `docs/bug-handling-process.md`
(регрессия существующего поведения = bugfix; новая возможность = feature). Критерий сюда
НЕ копируется — прочитай его по этим двум ссылкам и применяй их формулировку. Риск дрейфа
формулировок между intake и `/pipeline` шаг 0 принят осознанно: ссылка вместо копии, единый
сниппет не выносится (YAGNI до второго инцидента дрейфа; stage-2 ARCH-3).

**Асимметричный bias при неуверенности (FR-3):**

- интерактивная сессия → задай владельцу ОДИН уточняющий вопрос (I-13: не гадай, когда можно спросить);
- unattended-прогон → маршрут **feature** (сохраняет user-approval гейт пайплайна);
- деградация в bug-fast-path без ЯВНОГО сигнала «это баг/регрессия» запрещена: bug-путь
  обходит гейт владельца (дорогая ошибка), фича-путь для бага — просто дороже (приемлемо);
- пустая/односложная фраза: интерактив → один вопрос; unattended → отклони с подсказкой
  формата (`/intake "<фраза>"`); stage-1 на пустом входе не стартует.

## Шаг 2а — ветка bugfix: маршрут и стоп

Иди в `docs/bug-handling-process.md` §1 (issue полной структуры + fix-пак немедленно, БЕЗ
4-этапного пайплайна) и исполни его как есть — сам процесс не меняется. `pipeline-state.sh init`
НЕ вызывай (его scope-guard на bugfix — вторая линия защиты, не рассчитывай на неё).
После маршрутизации работа /intake ЗАВЕРШЕНА — stage-1 не стартует.

## Шаг 2б — ветка feature: фиксированный порядок (SPEC_DIR ДО тикета, Д-2)

0. **Advisory спек-дедап (FR-14):** штатным Grep-tool поищи ключевые слова фразы по
   `specs/*/spec.md` и `specs/*/state.md` — фраза/слова передаются как ПАРАМЕТР Grep-tool,
   shell-команду `grep "<фраза>"` не собирай (SEC-4). Совпадение → спроси владельца:
   «похоже, уже есть specs/NNN-…, продолжить?» — это advisory, не блокер: при подтверждении
   (или в unattended) продолжай.
1. **NNN/slug + mkdir-guard:** NNN = следующий номер в `specs/` (три цифры), slug =
   транслитерация первых 3-4 слов фразы. `mkdir "specs/<NNN>-<slug>"` — атомарный POSIX-guard
   NNN-гонки. EEXIST → пересчитай NNN и повтори ОДИН раз; второй EEXIST подряд → СТОП с
   ошибкой владельцу (чужой N без проверки slug не занимать, SEC-6). Дальше `SPEC_DIR=specs/<NNN>-<slug>`.
2. **Init:** `bash scripts/pipeline-state.sh init "$SPEC_DIR" "<фраза>" feature` — 5-й
   позиционный (ticket) НЕ передавать, тикета ещё нет.
   - state.md уже существует → это **resume** (повторный /intake той же фразы): скрипт покажет
     `next:` — продолжай оттуда, новый SPEC_DIR не создавай (шаг 3 при этом безопасен: dedup
     поймает существующий тикет, link-ticket идемпотентен).
   - init упал FATAL **не** по scope-guard и **не** resume (права на specs/, диск, «N занят»
     после повтора) → СТОП: покажи владельцу die-текст дословно и тикет НЕ создавай
     (ROB-3: иначе возвращается тикет-сирота, который устранён порядком Д-2).
3. **Тикет (best-effort):** `bash scripts/intake.sh ticket "$SPEC_DIR" "<summary>" "<фраза дословно>"` —
   summary = краткая тема (сама фраза, если она ≤ ~100 символов); 4-й аргумент — фраза
   ДОСЛОВНО, без редактуры. Скрипт сам ставит `[Owner]`-префикс, дедапит, verify-читает и
   вызывает link-ticket. Исход — одна строка stdout:
   - `created:<KEY>` → запомни KEY для маркера шага 4;
   - `deferred:public-repo` → в интерактиве покажи владельцу: «репозиторий PUBLIC — дословная
     фраза уйдёт в публично читаемый issue», дождись ЯВНОГО confirm → повтори тот же вызов с
     `INTAKE_ALLOW_PUBLIC=1`; отказ владельца или unattended → продолжай без тикета (KEY пуст);
   - прочие `deferred:*` → покажи владельцу ОДНУ строку-рецепт со stderr скрипта
     («Тикет отложен: … догон: `bash scripts/pipeline-state.sh link-ticket …`») и продолжай:
     спека обязательна, тикет догоняется (FR-10, I-8); KEY пуст (кроме `verify-failed KEY=<key>` —
     покажи KEY владельцу для ручного link-ticket после проверки, маркер НЕ ставь);
   - `error:*` → покажи причину; stage-1 всё равно продолжается без Ticket (NFR-2).
4. **Спека + маркер (FR-13):** делегируй механику `/speckit.specify "<фраза>" SPEC_DIR=$SPEC_DIR` —
   сырая фраза идёт как есть (доуточнение — зона NEEDS CLARIFICATION спеки и `/speckit.clarify`
   внутри stage-1; отдельный clarify-гейт не строится, Д-3). Затем маркер в шапке spec.md —
   только `perl -pi -e` (BSD/GNU-нейтрально, ROB-6; `sed -i` запрещён). ВАЖНО: маркер —
   канонический **bullet** `- Источник: тикет KEY` (blockquote `>` НЕ распознаётся
   `spec-lint.sh`/`dora-metrics.sh` — регекс `^[-*>]?…`; фикс латентного бага 005, 2026-07-04):
   - KEY непуст:
     `grep -qE '^[-*>]?[[:space:]]*Источник: тикет ' "$SPEC_DIR/spec.md" || KEYV="<KEY>" perl -pi -e '$_ .= "\n- Источник: тикет $ENV{KEYV}\n" if $. == 1' "$SPEC_DIR/spec.md"`
   - KEY пуст: `perl -pi -e '$_ = "" if /^[-*>]?\s*Источник: тикет/' "$SPEC_DIR/spec.md"` — строка
     удаляется целиком, шаблонный плейсхолдер не остаётся. Проверь: `bash scripts/spec-lint.sh "$SPEC_DIR"`
     не даёт тикет-warn на пустом месте.
5. **Авто-старт stage-1:** делегируй `/pipeline-stage1 "<фраза>" SPEC_DIR=$SPEC_DIR` — именно
   механику stage-1, не полный `/pipeline` с нуля (A-3; resume-семантика init делает повторный
   вход безопасным). Дальше работает штатный пайплайн — /intake его не дублирует (NFR-5).
